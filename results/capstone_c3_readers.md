# Criterion 3 (revised) — three stand-in readers

Three separate AI agents, one after another, each started with no context:
only the repository URL, an empty folder, and an empty model cache
(`HF_HOME` pointed inside that folder). Each was told to follow `RUNNING.md`
from `git clone` to the `curl` example returning a `label`, and to list every
point where it needed something neither `RUNNING.md` nor an error message told
it. Nothing in the repo changed between runs. All three ran on the same
machine — an Apple M4 Pro Mac, where plain `python3` is 3.15.2 and
`python3.13` is installed.

| Run | Reached a label? | Points needing outside help | Time |
|---|---|---|---|
| 1 | yes | 0 | about 5–6 min |
| 2 | yes | 0 | about 3–5 min |
| 3 | yes | 0 | about 1–2 min |

## What each did

All three: cloned, read `RUNNING.md`, saw that `python3` was 3.15 and used
`python3.13` as the file says, created the venv, `pip install -r
requirements.txt`, `python test.py` (9 passed), `python detector.py` (downloaded
gpt2, 526 MB, into the empty cache; perplexity 12.5, model_signal 0.8864),
`gunicorn -c gunicorn.conf.py app:app`, then the `curl` from `RUNNING.md`, then
stopped the server.

## What they noticed that didn't count as a blocker

- **`test.py` showed no WARN.** `RUNNING.md` says to expect "one WARN: model
  not downloaded". All three saw 9 passed and no WARN, because `test.py` checks
  `~/.cache/huggingface`, where this machine already had gpt2 — not the empty
  `HF_HOME` the test set up. An artifact of the test, but it means `RUNNING.md`
  and `test.py` disagree about where the model lives. (All three runs.)
- **Getting a supported Python isn't covered.** `RUNNING.md` says to use
  `python3.13`, `3.12` or `3.11`, but not how to install one. Here 3.13 was
  already installed; a reader without it would have needed help. (Runs 1 and 2.)
- **The `label` is a sentence.** The short answer is in `guess`; a reader
  expecting a one-word label might be surprised. (Run 3.)
- **A fresh clone already has the author's logs**, because `logs/` is
  committed. (Run 3.)
